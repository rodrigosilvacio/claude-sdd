Tutorial de AWS Kiro

O AWS Kiro trabalha com specs: arquivos que descrevem o que construir antes do código. Uma spec de feature gera requirements.md, design.md e tasks.md. Uma spec de bugfix usa bugfix.md no lugar de requirements.md. O Kiro está disponível em IDE, CLI, Web e Mobile.

Projeto_Exemplo: este tutorial usa o projeto “Lista de Tarefas” como exemplo.

O ciclo do Kiro

O ciclo tem quatro etapas: requisitos, design, tarefas e execução. Na execução, as tarefas rodam em ondas paralelas, conforme as dependências entre elas.

Linha do tempo de uma spec

Cada etapa deixa um registro que você pode revisar antes de seguir para a próxima.

  1. Requisitos Gera requirements.md (ou bugfix.md).
  2. Design Gera design.md.
  3. Tarefas Gera tasks.md.
  4. Execução em ondas paralelas As tarefas rodam conforme as dependências.

Fluxos de spec

Para features, o Kiro oferece dois fluxos: Requirements-First e Design-First. Há também o Quick Spec. Para correções de falhas, existem as specs de bugfix, que usam bugfix.md. No exercício, você compara o Design-First e o Quick Spec com o Requirements-First.

Passo a passo

Use os botões Anterior e Próximo para percorrer os seis passos.

  1. Instalar o CLI Kiro também está disponível em IDE, Web e Mobile. Comando de instalação: 
    curl -fsSL https://cli.kiro.dev/install | bash
  2. Escolher o fluxo da spec Requirements-First, Design-First ou Quick Spec; specs de bugfix usam bugfix.md.
  3. Gerar requirements.md Descreva o Projeto_Exemplo “Lista de Tarefas” e revise o arquivo.
  4. Gerar design.md Revise as decisões de design antes de seguir.
  5. Gerar tasks.md Confira a lista de tarefas gerada.
  6. Executar as tarefas As tarefas rodam em ondas paralelas conforme as dependências.
